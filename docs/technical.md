# Technical notes

`order_api/app.py` contains the catalog, `OrderRequest` validation model, `OrderResponse` model,
and `create_app` factory. FastAPI parses the request and Pydantic enforces strict field types and
forbids extra keys. The handler checks catalog membership after validation. This separates a bad
schema (422) from an absent product (404).

`order_api/database.py` contains `initialize_database`, `create_order`, and `get_order`. The
application lifespan creates the table if necessary. Each operation opens its own connection and
closes it explicitly. Write operations use a transaction context, so errors roll back and successful
writes commit. SQL values use placeholders rather than string concatenation. The database uses a
STRICT table, a primary key, NOT NULL fields, and CHECK constraints for catalog IDs, quantity,
positive prices, and arithmetic consistency. The catalog remains the HTTP service's source of prices.
SQLite 3.37 or newer is required for STRICT tables; the tested bundled SQLite version is recorded
in the execution evidence. This project does not implement schema migrations.

One row is one order, containing one catalog product. IDs are generated by SQLite. All prices and
totals use whole-THB integers, so there is no floating-point currency rounding. Very large positive
lookup IDs cannot fit SQLite's signed 64-bit key; they return the same 404 as other absent IDs.

`tests/test_orders.py` exercises the HTTP application via TestClient. Every fixture uses a temporary
file database. Rejection tests check HTTP status, the error structure, and the database count; the
parameterized request tests also seed and re-read an existing order to verify it remains unchanged.
The restart test creates two separate application instances against the same temporary file.

`scripts/smoke_test.py` runs a real local Uvicorn server in a background thread with an isolated database.
The fixture binds an OS-selected port and gives the socket to Uvicorn. HTTPX sends requests over TCP;
this is a live HTTP test, not a TestClient transport. The script requests graceful shutdown and joins
the server thread before removing its temporary database. It does not launch a visible window.
